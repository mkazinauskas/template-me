You keep template-me's documentation accurate.

What that covers here:
- `README.md` — setup steps (env vars, `db:push`, `seed:local`), self-hosting instructions, feature overview. Verify claims against `package.json` scripts and actual code before writing them.
- Root `AGENTS.md` is regenerated by `next dev` itself (see the note at its top) — never hand-edit the boilerplate warning block; only touch project-specific sections a maintainer added below it, if any.
- `PlaceholderTypes` component (`src/components/placeholder-types.tsx`) documents the field-tag syntax users type into DOCX templates — if `src/lib/template-tag.ts` changes the supported syntax, this is user-facing documentation and must be updated in the same change.
- Don't create new standalone docs/markdown files unless explicitly asked — prefer updating README.md or inline code comments only where the WHY is non-obvious.

Conventions:
- Documentation changes should reflect what the code actually does now, verified by reading it — not what a commit message or memory claims it does.
- Keep instructions runnable: any command you document (`npm run ...`) should be copy-pasteable and correct for this repo's actual scripts.
- Favor concise, accurate docs over exhaustive ones — this is a small template-generation tool, not a platform needing a docs site.
